# 专业度引擎 · professionalism

> v2.11 新增，v2.12 重构定档逻辑，v2.13 补叙事域与历史/小说路由。本文件解决去 AI 味引擎的反向副作用：**为了"像人说话"把话说碎、说浅、说得读者读不懂。**
>
> **一句话定位**：`de-ai-flavor.md` 是减法，本文件是承重结构。**减法可以砍装饰，不能砍承重墙。**
> 判断顺序固定：**先定档（专业度），再去味（人味）。** 反了就会出现"很顺、很像聊天，但读完不知道说了什么"。

---

## 一、病根：去味三刀砍到了承重墙

| 去味动作 | 正确对象 | 砍错之后的症状 |
|---|---|---|
| 删铺垫、删连接词 | 通知词、姿态声明、垫词 | 论证断裂：两个判断之间没有推导，读者接不上 |
| 结论前置、句子切短 | 绕弯长句 | 全文都是断句和半句，主线消失，读完复述不出三段 |
| 禁术语、禁冒号、禁解释 | 空泛工具名、假严谨 | 该给的定义没给，该讲的机制跳过，外行看不懂、内行觉得空 |

**判词（写完通读时问自己）**：**一个不懂这行的人读完，能不能复述出三个要点？** 复述不出，就是砍过头了，不是读者水平问题。

## 二、专业度四件套（每个核心判断都要配齐）

一条能立住的判断 = 下面四样至少三样，缺两样就是随笔。

| # | 件 | 具体是什么 | 反例（空） | 正例（实） |
|---|---|---|---|---|
| 1 | **机制** | 为什么会这样，因果链说清 | 「这样容易出错」 | 「柱子用长度表达数，长度有零点，零点一挪比例就变」 |
| 2 | **规格** | 数字、阈值、版本、时长、成本 | 「分片太多读不清」 | 「超过四片，扇形之间的差异肉眼分不出」 |
| 3 | **边界** | 什么时候不成立、什么人不适用 | 「照这个做就行」 | 「折线图可以截断纵轴，前提是轴上标出起点」 |
| 4 | **动作** | 在哪个入口、点哪里、敲什么 | 「调一下就行」 | 「右键纵轴→设置坐标轴格式→最小值填 0」 |

**抽骨测试**：把某个判断单独拎出来，删掉四件套，剩下的如果只是一句"正确的废话"，它就是空话，要么补料，要么删。

> 四件套的配比随档位浮动：L3 重动作与规格，L4 重机制与边界，L2 有机制就够，L1 只需一件真东西（真场景或真判断）。**四件套是通用的骨架，不是每档都要求全配。**

### 2.1 承重件随「域」换（重要）

上面四件（机制／规格／边界／动作）是**论说域与操作域**的承重件。叙事类内容套这四个会立刻写歪——故事不讲"机制"，讲"这个人为什么这么干"。

先认域，再挑承重件：

| 域 | 装什么内容 | 承重四件 | 缺了会怎样 |
|---|---|---|---|
| **论说域** | 观点评论、行业观察、方法论、横评、数据分析 | 机制／规格／边界／动作 | 只有立场没有依据，或只有结论没有适用条件 |
| **操作域** | 工具教程、速查清单、通知公告 | 入口／参数／验收／失败处理 | 读者照着做会卡住，卡住之后没人管 |
| **叙事域** | **历史故事、个人随笔、复盘、人物、纪实** | **动机／细节／冲突／节奏** | 事讲完了但没人信，或者没人想往下看 |
| **抒怀域** | 散文、抒情随笔、演讲 | 场景／心境／转折／余味 | 变成空泛抒情，读完什么都没留下 |

**叙事四件的具体要求**：

| 件 | 是什么 | 反例（空） | 正例（实） |
|---|---|---|---|
| **动机** | 这个人为什么非这么干不可，代价是什么 | 「他决定反抗」 | 「他若不反，明年这家店的地契就不在他手上」 |
| **细节** | 可感的物、动作、数字、气味，能拍出来的东西 | 「气氛很紧张」 | 「他把茶碗放下，碗底在桌上转了半圈才停」 |
| **冲突** | 谁跟谁顶上了，双方各要什么，退让的代价 | 「遇到了困难」 | 「老板要三天交，客户要七天改，中间只有他一个人」 |
| **节奏** | 信息给的顺序与延迟——先给什么、瞒什么、什么时候抖开 | 从头按时间顺序讲完 | 先给结果，再回头补那三天里发生的事 |

> 叙事域不要求"逻辑严密"，要求"可信"。**可信不来自形容词，来自细节与动机对得上。** 一个人物说他要放弃，那就得在前面某处埋过一件让他撑不住的小事。

## 三、定档：由内容决定，不由账号决定

**"这个号该用什么档"是错的问法。** 同一个号，教程是 L3，随笔是 L1，评论是 L2，年度复盘是 L4。**档位跟着这一篇的读者任务走，不跟着账号走。**

### 3.1 四档刻度

| 档 | 语言松紧 | 每段信息量 | 读者读完的状态 | 术语处理 |
|---|---|---|---|---|
| **L1 漫谈** | 最松，可口语、可跑题 | 低，一段一件事 | 有共鸣，想起自己的事 | 少用；用了随口解释 |
| **L2 评论** | 中，有立场也有铺垫 | 中，一段一论点 | 有了立场，知道自己站哪边 | 允许，但要给出处 |
| **L3 教程** | 紧，句子完整，逻辑外露 | 高，一段一动作或一坑 | 手上有了一件能用的东西 | 首次出现给一句白话解释 |
| **L4 分析** | 最紧，可用长句铺因果 | 最高，一段一层 | 能自己做同类判断了 | 术语给定义，允许保留专业词 |

### 3.2 定档四问（按顺序问，第一个"是"命中即定档）

| 序 | 问 | 命中 → 档 |
|---|---|---|
| 1 | 读者读完要**动手做一个动作**，做完这件事才算成？ | **L3** |
| 2 | 读者读完要**做一次取舍或判断**（选哪个、该不该、为什么会这样）？ | **L4** |
| 3 | 读者读完要**站一个立场**（同意谁、反对谁、怎么看这件事）？ | **L2** |
| 4 | 读者读完只需要**共鸣、陪伴、被说中**？ | **L1** |

顺序不能调。四问同时命中时取最靠前的一档，因为越靠前的读者任务越硬——**读者要动手的时候，你给他立场，他照样不会做。**

### 3.3 混合档规则

一篇允许**主档 + 辅档段落**，但比例有硬线：

| 主档 | 允许的辅档段落 | 上限 | 典型用法 |
|---|---|---|---|
| L3 教程 | L1 场景 | ≤15% | 开头用一段真实场景切入，第二段立刻转教程 |
| L4 分析 | L3 操作 | ≤20% | 分析完给一段"你自己怎么验" |
| L2 评论 | L1 叙事 | ≤25% | 用一件事开场，再抽判断 |
| L1 随笔 | 不建议混 | — | 混进 L3 的动作段会立刻散架 |

**主档的判断标准**：删掉辅档段落，文章还成立 → 辅档；删掉就没了骨架 → 那就是主档，重新定档。

### 3.4 常见误判

| 症状 | 实际是 | 怎么改 |
|---|---|---|
| 通篇短句、句句带梗，读者读完不知道干啥 | 该 L3 写成了 L1 | 补动作、补参数、每段末尾落到"所以你点哪里" |
| 教程写到一半开始抒情、发感慨 | L1 段混进 L3 骨架 | 感慨删掉或压成一句，放段末 |
| 观点文写成步骤清单，但没有立场 | 该 L2 写成了 L3 | 每段补"我认为/我不看好"的明确判断，别只给方法 |
| 分析文只有结论没有机制 | 该 L4 写成了 L2 | 每个结论补一句因果链，补一条失效条件 |
| 全篇一个调，哪档都不像 | 没定档 | 回到 3.2 四问，重定一次 |

## 四、文体结构库（按文体选骨架，不按模板套）

**档位定语言，文体重结构。** 同一档里，教程和避坑复盘的信息顺序不一样，套错骨架比定错档更容易看出破绽。

### 4.1 结构清单

| 文体 | 档位 | 骨架（顺序即段落顺序） | 最容易写砸 |
|---|---|---|---|
| **工具教程** | L3 | 能干什么（用第三方场景，不用跑分）→ 谁能用（版本/机型/额度门槛）→ 替你干哪件活 → 怎么开始（入口·参数·验收）→ 卡住了怎么办 | 从功能介绍开场，读者不知道跟自己有什么关系 |
| **速查清单** | L3 | 一句话说清适用场景 → 清单主体（分组，每条≤2 行）→ 哪几条不适用 → 最容易漏的那一条 | 清单条目全是形容词，没有可执行的动词 |
| **避坑复盘** | L3 | 结果（翻车或成功）→ 现场细节 → 三个可疑原因 → 哪个是真原因 → 下次怎么改 | 只讲现象不落因果，读者看完只会怕 |
| **观点评论** | L2 | 判断先行 → 依据（2–3 条）→ 承认反方最强的那一点 → 回应 → 落回读者处境 | 两边都说，最后没有立场；或只骂不给替代 |
| **行业观察** | L4 | 一个具体现象（带数据）→ 机制（为什么现在发生）→ 谁受影响 → 反例/失效条件 → 我的判断 | 从宏观叙事开场，没有可验证的落点 |
| **横评选型** | L4 | 先定维度（对齐规格再比）→ 逐维对比表 → 谁适合谁（分档对号）→ 什么情况都不建议 | 先给排名后给维度，顺序反了就是软文 |
| **方法论拆解** | L4 | 问题为什么难 → 拆成几步/几层 → 每层的机制 → 一个反例 → 适用边界 | 只给框架不给步骤，读完记住了名词不会用 |
| **数据分析** | L4 | 一句话结论 → 数据来源与口径 → 3–5 个关键发现 → 最反直觉的那个单独讲 → 对应行动 | 口径不说清，结论再漂亮也不敢信 |
| **工作汇报** | L4 | 结论/要什么（第一句）→ 背景（≤3 句）→ 进展与数据 → 风险与卡点 → 下一步与需要谁配合 | 按时间顺序讲过程，领导读到第三屏才看见结论 |
| **产品介绍** | L2 | 读者现在怎么受苦 → 它换掉了哪一步 → 三条可验证的能力（带数字）→ 谁不适合 → 怎么试 | 全程形容词，没有一条能验证 |
| **种草笔记** | L1→L2 | 结果图或结果句 → 我为什么试 → 使用过程（写细节不写形容词）→ 缺点直说 → 适合谁 | 全是"绝了""爱了"，没有一次具体操作 |
| **短视频口播** | L1→L2 | 前三秒钩子（反常识或损失）→ 一句结论 → 两三个要点（口语短句）→ 一个可执行动作 → 收尾留钩 | 前五秒自我介绍，完播率直接掉光 |
| **个人随笔** | L1 | 一个具体场景 → 当时的判断（可以承认是错的）→ 后来遇到的事 → 现在的看法 → 停在画面 | 结尾升华、总结道理，把读者的感受替他说了 |
| **演讲致辞** | L2 | 一个共同处境 → 一个反常识判断 → 两个例证 → 落到在场的人 → 一句收束 | 排比堆情绪，没有一句能被记住的具体话 |
| **通知公告** | L3 | 谁要做什么（第一句）→ 时间·地点·材料 → 怎么办（步骤）→ 找谁问 | 开头先写背景和意义，读者找不到"我该干什么" |
| **书评影评** | L2 | 一句话结论 → 它做对了什么（具体段落/镜头）→ 它没做到什么 → 适合谁看 | 复述剧情代替评价，或通篇褒贬没有依据 |
| **历史故事** | L1→L2 | 反常结果（先给谜面）→ 现场物证或原文 → 三种解释 → 排除两种 → 剩下即结论 → 标清每句的史实层级 → 留一句"至今无定论" | 从头按年代讲一遍，读者在上半段就走了；把传说当正史用 |
| **历史解读** | L4 | 一个流传很广的说法 → 原文到底怎么写的 → 后人怎么改的 → 为什么要改（改的人得到什么）→ 今天的对应 | 只做"辟谣"不给动机，读者不知道为什么这个错能传一百年 |
| **人物纪实** | L1→L2 | 他现在的一个具体动作 → 走过来的三件事（只留决定性的）→ 他当时的判断依据 → 付出的代价 → 停在一个具体瞬间 | 从小时候写起；用形容词代替他做过的事 |
| **小说／剧本** | — | **不在本技能范围，转 `qianjin-novel-writer`（网文小说写作，另一套人物与章节规范）** | 用论说或教程的骨架写小说，人物立不住 |
| **新闻通稿** | L4 | 详见 `news-press-release.md`（另有一套完整规范，不在此重复） | — |

### 4.2 历史故事的硬约束：史实分层

历史题材不是"写得像"就行，**它有一条别的体裁没有的红线：不许把传说当正史用。** 四层材料，四种用法：

| 层 | 材料 | 能怎么用 | 不能怎么用 |
|---|---|---|---|
| **甲** | 正史原文、一手档案、当事人记述 | 可作论据、可打引号 | — |
| **乙** | 注家异说、后世史评 | 作支线，或作"第二种解释" | 不能当唯一依据 |
| **丙** | 考古发现、学界争议 | **优先做开场钩子**（最有"咦"感） | 不能说成"史书记载" |
| **丁** | 民间传说、影视演绎、网络段子 | 可造悬念、可做引子 | **必须当场点破**，绝不作论据 |

判定式：**读者能不能从你的句子里分辨出哪句是史料、哪句是后人加的？** 分辨不出，就是层没标清。

历史故事还有三种高转化形态，相邻两篇不要同型：

| 形态 | 结构 | 落点 |
|---|---|---|
| **悬疑型** | 反常结果 → 物证 → 三种解释 → 排除两种 → 剩下即结论 | 结尾留"至今无定论"，引评论 |
| **八卦型** | 谁跟谁、为什么、撕到什么程度 → 动机剖析 → 换成今天的同款关系 | 落点是**关系结构**，不做道德审判 |
| **古今对比型** | 同一件事：古代流程 vs 今天流程两栏并列 → 差异背后同一个不变的东西 | 不做"今不如昔"的感叹 |

### 4.3 按交付物反查文体

用户没说写什么文体时，看他要的**交付物**：

| 用户想要 | 该用文体 | 档位 |
|---|---|---|
| 能照着做出来 | 工具教程 / 速查清单 | L3 |
| 能填的表、能交的汇报 | 工作汇报 / 数据分析 | L4 |
| 能粘的提示词、模板 | 速查清单 | L3 |
| 能跑的命令、配置 | 工具教程 | L3 |
| 能对照着选的表 | 横评选型 | L4 |
| 一个说法、一个立场 | 观点评论 | L2 |
| 一个能发出去的内容（笔记/口播） | 种草笔记 / 短视频口播 | L1→L2 |
| 一段读起来舒服的东西 | 个人随笔 / 书评影评 | L1 |
| **一个想知道"后来呢"的故事** | **历史故事** | L1→L2 |
| **一个"原来是这样"的恍然大悟** | **历史解读** | L4 |
| **一个真实的人，读完记住他** | **人物纪实** | L1→L2 |
| **一章小说、一集剧本** | **转 `qianjin-novel-writer`** | — |

### 4.4 小说与虚构叙事：转技能，不硬塞

小说、短篇、剧本、网文连载**不用本技能的四档和体裁表**，原因有三：

1. **评价标准不同**。虚构叙事的成败在人物弧光、章节钩子、冲突升级、伏笔回收，不在"机制/规格/边界/动作"，也不在"读者读完能不能复述三个要点"。
2. **节奏单位不同**。一篇公众号是 2000 字一个完整结构；一章网文是 2000 字一个卡点，要求结尾必留钩。用文章骨架写小说，会写出"没有章节感"的平铺。
3. **已有专门技能**。`qianjin-novel-writer`（网文小说写作）有独立的章节规范、人物设定、三审流程、平台适配，重复实现只会两套规则打架。

**路由规则**：
- 用户说"写小说／短篇／连载／剧本／同人／网文"→ 直接用 `qianjin-novel-writer`。
- 用户说"写个故事"但语境是公众号推文、品牌叙事、案例故事 → **仍在本技能内**，用 4.1 的「历史故事」或「人物纪实」骨架，走叙事域四件。
- 判断分界：**读者是来读故事本身的（虚构作品）→ 转技能；故事只是文章的载体（说理、带货、立人设）→ 留在本技能。**

### 4.5 骨架不是模板

上表给的是**信息顺序**，不是段落数。允许：
- 合并相邻两段（内容少时）；
- 调整中段顺序（前提是读者不需要前一段的信息才能读懂后一段）；
- 加一段"我的一个反例"（L2/L4 常用，很提可信度）。

不允许：
- 删掉骨架里的**最后一个动作段**（L3 的"怎么开始/卡住怎么办"、L4 的"行动/边界"）——那是读者真正拿走的部分；
- 把骨架顺序当成小标题写法。小标题仍按第五节：写这一段的核心判断，不写"第一步""背景介绍"。

## 五、自动匹配：按用户需求定档，不按习惯定档

**目标**：用户只说"帮我写篇关于 X 的"，也能自动匹配到对的档位和文体，不用反问，也不用一律套 L3。

### 5.1 抓六个信号

从用户请求里找这几样，能找到几样算几样：

| 信号 | 从哪看 | 影响 |
|---|---|---|
| **平台** | 公众号／小红书／抖音／知乎／B站／内部汇报 | 决定文体池（小红书偏 L1→L2，知乎偏 L3/L4，口播偏 L1→L2） |
| **读者** | 同行／客户／领导／陌生人／粉丝 | 同行可上 L4，陌生人必须 L3 以下且给定义 |
| **目的** | 教会／说服／取悦／汇报／记录 | 直接对应定档四问 |
| **交付物** | 能做什么、能拿走什么 | 用 4.2 反查文体 |
| **动词** | "怎么做""为什么""该不该""聊聊" | 见 5.2 词表 |
| **篇幅与时间** | 字数、期限、要不要配图 | 短篇（<800 字）慎用 L4，铺不开机制 |

### 5.2 动词 → 档位速查

| 用户说的词 | 档位 | 文体候选 |
|---|---|---|
| 怎么做、步骤、教我、上手、配置、设置、跑通 | L3 | 工具教程 / 速查清单 |
| 为什么、哪个好、对比、拆解、评估、选型、值不值 | L4 | 横评选型 / 方法论拆解 |
| 该不该、怎么看、我认为、回应、评价 | L2 | 观点评论 / 书评影评 |
| 聊聊、记录、感受、随笔、分享一下心情 | L1 | 个人随笔 |
| 汇报、总结、复盘、周报、方案 | L4 | 工作汇报 / 数据分析 |
| 种草、推荐、带货、口播、脚本 | L1→L2 | 种草笔记 / 短视频口播 |
| 讲个历史上的事、这段历史怎么回事、后来呢 | L1→L2 | **历史故事**（叙事域四件；必须标史实层级） |
| 这段历史说明什么、为什么会这样、真实的 XX 是怎样的 | L4 | **历史解读** |
| 写个人的故事、把他的经历整理出来 | L1→L2 | **人物纪实** |
| **写小说、短篇、连载、网文、剧本、同人** | — | **不在本技能，转 `qianjin-novel-writer`** |

> ⚠️ 「讲个故事」这五个字有歧义，必须再问一层：**读者是来读故事本身的 → 转小说技能；故事只是文章的载体（说理、带货、立人设、讲历史）→ 留在本技能。** 别一看"故事"就套个人随笔的骨架。

### 5.3 判定流程（四步，不反问）

```
① 抓信号（5.1 六项，缺项跳过）
② 定档（3.2 四问，从最硬的任务问起）
③ 选骨架（4.1 按文体，或 4.2 按交付物反查）
④ 声明判定（开工前一句话，允许用户改）
```

### 5.4 声明格式（写在前，不写在后）

判定完先给一句，再动笔：

> 按**教程档（L3）·工具教程**骨架写：你提到"教我怎么用"，读者目标是照着做出结果，所以给入口、参数、验收。
> 要改成评论档（L2）或分析档（L4），说一声我调。

这一句的作用是**把自动匹配变成可撤销的**——不问，但也不藏。用户看到判定结果，觉得不对立刻能改，比反问一轮更快。

### 5.5 信号不足时

只说了主题、什么都没说（"写篇关于 XX 的"）：

- 默认 **L2 · 观点评论**，不是 L3。理由是：没有任何"要动手"的证据时，把读者当"要判断"的人最安全——写成教程却缺参数会误导，写成评论仍有信息价值。
- 仍然给 5.4 的声明，把假设说清。
- 不因为这个默认值就不看内容：一旦正文写到具体操作，立刻升到 L3 并补参数。

### 5.6 多意图时取主交付物

一句请求里同时有"教会我"和"说说你的看法"：取**读者最终要拿走的东西**。要拿走动作 → L3，动作讲完带一段判断（辅档）；要拿走立场 → L2，判断里嵌操作方法（辅档）。不要一半教程一半评论，读者两头都拿不到。

## 六、标题钩子引擎（六类，必选其一，不许"叙述型标题"）

**叙述型标题**＝把文章内容概括一遍，信息全对，但没有让人点开的理由。典型：「数据没错，是图让人读反了」「三种模式怎么选」「关于 XX 的几点思考」。这类标题的正确率越高，打开率越低。

| 类型 | 公式 | 例 | 适用档 |
|---|---|---|---|
| **代价型** | 一个具体损失 + 归因 | 「4.6% 的跌幅，被一张图看成腰斩」 | L3/L4 |
| **身份型** | 锁定人群 + 他们的处境 | 「做周报的人，一半栽在这张图上」 | L2/L3 |
| **数字反差** | 小数字 vs 大后果，或反过来 | 「改了纵轴一个数，结论反过来了」 | L3/L4 |
| **结论冲突** | 常识怎么说 vs 实际怎么样 | 「柱状图不从零起，不是难看，是错」 | L4 |
| **结果承诺** | 多久/多省/多快，给可验证的量 | 「六类问题一张表，配图不用再猜」 | L3 |
| **缺口型** | 只给一半信息，留一个必须点开的空 | 「它画图前会先问你四句话」 | L2/L3 |

> 档位与钩子的对应只是倾向，不是限制：L1 随笔用「身份型」同样成立（「在北京租房的第三年，我学会不看面积」）。

### 标题自检三条（全过才算合格）
1. **有具体名词**：产品名、数字、场景、人群，至少一个。全是抽象词＝没钩子。
2. **有得失**：读者能看出"看了能少踩什么坑 / 多拿什么"，或"不看会错在哪"。
3. **可转述**：别人能一句话把这标题讲给同事听，不用解释背景。
4. 附加：**遮住正文，标题自己站得住**；≤22 字；负面句式（先别／别急／不一定／还在翻车／接不住）受配额限制。

## 七、小标题：一段的核心判断，不是一句意象

**上一版的错误**：为了不像教案，把小标题写成意象短句（「那个"撤"字」「八个字」）。结果读者扫目录扫不出信息，读到中途也不知道这段在讲什么。

**正确标准**：**小标题是这一段论点的浓缩，单独读也要成立，并且能当一句话讲给别人听。**

| 写法 | 结构 | 例 |
|---|---|---|
| **判断式** | 主语 + 明确的判断 | 「柱状图的起点必须是零」 |
| **因果式** | 因为 A，所以 B | 「轴一挪，比例就变了」 |
| **对比式** | A 行，B 不行 | 「长度会撒谎，位置不会」 |
| **数字式** | 数量 + 结论 | 「饼图超过四片，读者只能猜」 |

### 三条禁令
- **禁纯意象**：只有画面没有判断（「那个字」「八个字」「一张纸」）→ 补成判断。
- **禁设问通知**：`为什么……` / `怎么才能……` 当小标题，是把提纲当标题。
- **禁编号**：不写「第一步」「一、二、三」；顺序靠内容推进，不靠序号。

> 例外：L1 随笔允许用**名词性场景小标题**（「那天下午」「一把伞」），因为随笔的段落功能是场景推进而非论点推进。但 L2/L3/L4 一律按上表。

### 串联自检
把全部小标题抽出来单独读一遍：**能不能连成一篇的骨架？读完知不知道全文在讲什么？** 连不成，就是小标题没承担信息。

## 八、可读性闸门（成稿前必过，五项）

1. **主线一句话**：全文能用一句话说清"教读者做什么判断/做什么动作"。说不出＝结构散了。
2. **段首见判断**：每段第一句就是这段的结论，后面才是解释。禁止"背景→背景→终于到结论"。
3. **术语首现解释**：专业词第一次出现，紧跟一句白话（括号或破折号后一句），后文不再解释。
4. **每 500 字一次收束**：一段讲完，用一句话把"所以对你意味着什么"落地，再进下一段。
5. **完整句比例**：L3/L4 全文完整句 ≥70%；连续不完整短句不超过 3 句。L1 不受此限。

---

## 九、与其它引擎的优先级（冲突时照此裁决）

```
专业度（本文件：承重） > 可读性 > 去 AI 味（人味） > 文学性
```

- 去 AI 味要求"短句、删铺垫"，专业度要求"机制讲清"→ **机制讲清优先**，用完整句讲，不用碎句凑人味。
- 去 AI 味要求"禁术语"，专业度要求"术语给定义"→ **给定义后照用**，不要为了口语把专业词换成模糊说法。
- 文学性永远排最后，一篇加点 ≤2 处。
- **定档不参与这个优先级**：档位是前置决策，不是可让步项。定错档之后做什么优化都是白做。

## 十、专业度自检六问（交付前，与七问并列）

1. 这篇定的是哪一档？**是按内容定的，还是按习惯定的**？四问里命中的是哪一问？
2. 体裁选对了吗？骨架的**末位动作段**（L3 的"怎么开始"、L4 的"行动/边界"、历史故事的"定论或存疑"）在不在？
3. **承重件按域查**：论说域→机制／规格／边界／动作；操作域→入口／参数／验收／失败处理；叙事域→动机／细节／冲突／节奏；抒怀域→场景／心境／转折／余味。
4. 标题属于六类钩子的哪一类？三条自检过了吗？
5. 小标题抽出来能连成骨架吗？有没有纯意象或设问？（L1 随笔可用名词性场景标题）
6. 一个外行读完，能不能复述三个要点？

> 第 6 问对**虚构叙事**（小说、剧本）不适用——那类要问的是"想不想看下一章"。虚构作品不归本技能，见 4.4 路由。

> 第 1 问是 v2.12 改的。原来问"语气和档位对得上吗"，那只检查执行；现在先检查**决策本身对不对**——档定错了，语气再贴也是错。
